# YanSnap 技术架构

本文面向希望理解、调试或贡献 YanSnap 的开发者，描述当前实现，而不是未来产品规划。

## 设计目标

YanSnap 保持以下技术边界：

- 原生 Windows x64 应用
- 单个主 EXE，便携包无需安装
- C++20 与 Win32 API
- 不依赖第三方 GUI 框架或运行时
- 截图数据在本机处理
- 空闲时保持较小的进程和内存开销

## 技术栈

| 模块 | 实现 |
| --- | --- |
| 窗口与输入 | Win32 User32、公共控件 |
| 屏幕捕获 | GDI 虚拟桌面捕获 |
| 窗口边界 | User32 与 DWM |
| 标注绘制 | GDI 与内存位图 |
| 文字识别 | Windows.Media.Ocr（C++/WinRT） |
| PNG 编码 | Windows Imaging Component |
| 剪贴板 | Win32 Clipboard API，优先 `CF_DIBV5` |
| 系统托盘 | `Shell_NotifyIcon` |
| 配置 | INI 文件 |
| 构建 | CMake、MSVC 与 Windows SDK |

MSVC Release 使用静态运行库 `/MT`，因此便携包不需要另行安装 Visual C++ Runtime。

## 目录结构

```text
src/
├─ app/         应用生命周期、单实例、快捷键、托盘和开机启动
├─ capture/     虚拟桌面捕获和窗口识别
├─ overlay/     截图遮罩、选区交互和浮动工具栏
├─ ocr/         本地文字识别和截图内嵌结果面板
├─ annotation/  标注对象与撤销/重做
├─ export/      图像合成、剪贴板和 PNG 编码
├─ pin/         置顶贴图窗口
├─ settings/    配置模型和设置窗口
└─ common/      Win32 RAII、图标和几何工具
```

`tests/` 同时包含可自动运行的单元测试和需要桌面交互的集成测试程序。

## 应用生命周期

`main.cpp` 启用 Per-Monitor DPI Awareness V2 并初始化 COM，然后创建 `App`。

`App` 负责：

1. 建立单实例
2. 加载设置
3. 创建隐藏主窗口
4. 创建系统托盘图标
5. 注册全局快捷键
6. 进入 Win32 消息循环

重复启动时，新的进程只通知已有实例显示后台状态，然后退出。程序不会因为双击 EXE 自动进入截图。

## 截图数据流

```text
全局快捷键 / 托盘菜单
        ↓
捕获完整虚拟桌面
        ↓
显示静态截图遮罩
        ↓
窗口识别或自由选区
        ↓
标注对象叠加
        ↓
ImageComposer 合成最终像素
        ├─→ ClipboardExporter
        ├─→ PngEncoder
        ├─→ PinWindow
        └─→ OcrPanel → Windows.Media.Ocr → 文本剪贴板
```

捕获发生在遮罩显示之前。已有贴图会在捕获前临时隐藏，并在桌面图像获取完成后恢复，避免工具自身进入截图。

OCR 使用当前选区的原始桌面像素，不包含用户后来添加的标注。点击工具栏 OCR 后，识别结果作为子面板显示在同一个截图遮罩内，截图会话不会结束，也不会创建独立的顶层结果窗口。

## 坐标与 DPI

内部选区和捕获数据使用虚拟桌面的物理像素坐标。虚拟桌面可能从负 X 或负 Y 开始，因此几何逻辑不能假设原点为 `(0, 0)`。

窗口和界面尺寸根据当前 DPI 缩放，进程使用 Per-Monitor DPI Awareness V2。涉及多显示器的修改应至少测试：

- 副屏位于主屏左侧或上方
- 不同显示器使用不同缩放比例
- 选区跨越显示器
- 捕获期间显示配置变化

## 窗口识别

`WindowDetector` 从光标位置查找可见窗口，过滤 YanSnap 自身窗口和不适合作为捕获目标的桌面辅助窗口。可用时优先读取 DWM 扩展窗口边界，以减少不可见边框造成的尺寸偏差。

窗口识别失败不会阻止截图，用户仍可自由拖选区域。

## 标注模型

编辑期间，标注以对象形式保存在 `UndoStack` 中，不直接修改原始桌面图像。完成截图时，`ImageComposer` 按顺序将标注渲染到选区像素。

当前标注类型：

- 矩形
- 箭头
- 画笔
- 文字
- 马赛克

马赛克在最终合成时直接修改像素块，而不是叠加可移除的半透明效果。

## 剪贴板与 PNG

`ClipboardExporter` 写入图像时使用 `CF_DIBV5`，写入 OCR 文本时使用 `CF_UNICODETEXT`，并在剪贴板被短暂占用时进行有限重试。读取剪贴板贴图时支持常见位图格式。

`PngEncoder` 使用 WIC 写入 PNG，支持 Unicode 路径。自动保存使用时间戳文件名，并为同秒重名文件追加序号。

耗时的自动保存不阻塞截图交互线程。失败时保留截图状态并向用户显示错误。

## 贴图窗口

`PinWindow` 持有独立的图像副本并创建置顶窗口。贴图支持：

- 拖动
- 以光标位置为锚点缩放
- 透明度调节
- 显示、隐藏和关闭
- 复制、保存和恢复 100% 比例

贴图关闭后通过窗口消息通知 `App` 释放对应对象。

## 本地文字识别

`OcrRecognizer` 将 BGRA 选区转换为 `SoftwareBitmap`，并调用 Windows.Media.Ocr。引擎优先选择已安装的中文语言，随后尝试用户配置语言、英文和其他可用语言。超过系统 OCR 最大尺寸的图片会等比例缩小后再识别。

识别在线程中执行，不阻塞截图界面。`OcrPanel` 是截图遮罩的子窗口，提供加载状态、可编辑文本框、复制全部和返回截图操作。结果中的换行会规范为 Windows 换行格式，并移除连续汉字之间由系统 OCR 产生的多余空格。

## 配置与便携模式

默认配置路径：

```text
%LocalAppData%\YanSnap\settings.ini
```

如果 EXE 同目录存在 `portable.flag`，配置改为：

```text
<YanSnap 目录>\config.ini
```

设置先写入临时文件，再原子替换正式文件。版本无效或损坏的配置会被备份并回退默认值。

## 开机自动启动

该功能默认关闭。用户启用后，`StartupManager` 在以下当前用户注册表位置写入 `YanSnap` 值：

```text
HKCU\Software\Microsoft\Windows\CurrentVersion\Run
```

值中保存带引号的当前 EXE 路径和 `--startup` 参数。取消选项会删除该值，不需要管理员权限。

## 隐私边界

主程序没有链接 WinHTTP、WinINet 或 Winsock 网络客户端。运行时不进行登录、遥测、上传和自动更新。

截图像素只会在以下用户主动操作后离开进程内存：

- 复制到 Windows 剪贴板
- 保存到用户选择的目录

OCR 图像和识别结果不通过网络传输。识别文本只有在用户复制后才会写入 Windows 剪贴板。

## 依赖策略

项目优先使用 Windows 系统组件。引入第三方依赖前应说明：

- 解决的问题
- 对发布体积和启动速度的影响
- 许可证
- 为什么现有 Windows API 或小型内部实现无法满足需求

录屏、云上传、账号系统和插件平台不属于当前核心架构。
